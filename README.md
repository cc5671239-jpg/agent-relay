# agent-relay —— 跨 Agent 的个人开发上下文层

> 换一个 AI，感觉还是同一个开发助手。

## 一个真实的问题

AI Coding 时代的个人开发者，工作流大多是这样：

```text
一个 AI 平台的免费额度用完
        ↓
切换到另一个 AI 平台
        ↓
继续开发同一个项目
```

比如：ZCode → Codex → Claude → Gemini。

但每切换一次，新 Agent 都是一个「失忆的天才」：

- 不知道**项目历史**——这是什么项目、做到哪一步了
- 不知道**设计决策**——当初为什么这么定，哪些不能推翻
- 不知道你的**开发习惯**——小步迭代还是大步快跑
- 不知道你的**审美标准**——什么算好看、什么碰都不能碰
- 不知道你的**工作流程**——改完要不要自己验证、能不能擅自部署

于是每次换工具，都要把助手重新「培养」一遍。

## 解决方案：一份跟着项目走的上下文

Agent Relay **不是**多 Agent 协作框架——不搞编排、通信、任务调度，也不绑定任何 AI 工具，不规定「谁负责开发、谁负责架构」。

它只是 **9 份 Markdown 文档 + 一套工作协议**，放在项目根目录。任何 Agent 只执行任务，上下文由 Relay 统一供给：

| 文件 | 回答的问题 |
|---|---|
| `AGENTS.md` | 入口：必读顺序、项目规则、红线 |
| `USER_PROFILE.md` | **用户是谁、怎么开发、喜欢什么**（用户的开发人格，跨项目稳定） |
| `WORKFLOW.md` | Agent 的标准工作协议：开工 / 执行 / 收尾 / 部署边界 |
| `PROJECT_CONTEXT.md` | 项目现在什么状态（目标 / 技术栈 / 版本 / 阶段 / 已完成 / 未完成 / 问题） |
| `HANDOFF.md` | 上一任 Agent 完成了什么、留了什么坑、下一任继续什么 |
| `ROADMAP.md` | 接下来往哪走 |
| `DECISIONS.md` | 为什么这样设计 |
| `CHANGELOG.md` | 改过什么、谁改的（必填工具 + 模型） |
| `CLAUDE.md` | 指针文件（兼容只认 CLAUDE.md 的工具） |

任何 Agent 进来，按 `AGENTS.md` 的顺序读一遍，5 分钟内就能知道：项目是什么、用户是谁、用户怎么开发、进度在哪里、下一步做什么。

**体验：今天 ZCode 开发，明天 Codex 接手，后天 Claude 接手——开发体验保持一致。**

## 三条铁律

1. **状态唯一载体是文档**，会话是一次性容器；文档没写 = 工作没做完
2. **收尾必推送**：git 远端是唯一备份，不 push = 工作只完成一半
3. **变更必署名**：每条 CHANGELOG 记录执行 Agent 的工具 + 模型，可追溯、可断代分析

另有一条画像红线：`USER_PROFILE.md` 必须来自用户本人确认，**严禁编造**。

## 明确不做的事

- ❌ 不做多 Agent 编排 / 多 Agent 通信 / 自动任务调度
- ❌ 不绑定具体 AI 工具，不按工具分工
- ❌ 不做企业级治理
- ✅ 只解决一件事：**个人开发者切换 AI 工具时，上下文与体验不丢**

## 安装（作为 Agent 技能）

```bash
# 克隆本仓库到个人技能目录（仓库地址在本页面右上角 Code 按钮获取）
git clone <本仓库地址> ~/.agents/skills/agent-relay   # ZCode / 跨工具标准目录
git clone <本仓库地址> ~/.claude/skills/agent-relay   # Claude Code
```

其他工具（Codex / Cursor 等）：把 `SKILL.md` 的内容放进你的系统规则文件，或直接让 Agent 阅读本仓库。

**触发方式**：对 Agent 说"接手项目 / 开工 / 收尾 / 交接"，技能会自动介入；也可以显式调用 `/agent-relay`。

## 为新项目初始化框架

对 Agent 说：

> 用 agent-relay 技能给本项目初始化接力文档

Agent 会把 `assets/templates/` 中的 9 份模板复制到项目根目录并按项目实际填写——其中 `USER_PROFILE.md` 会逐项询问你本人，不会编造。

## 从 v1 升级

项目里已经用了旧版 6 份文档？对 Agent 说：

> 用 agent-relay 技能把本项目从 v1 升级到 v2

Agent 会补齐 `USER_PROFILE.md` / `WORKFLOW.md` / `HANDOFF.md` 三份新文件，迁移旧内容（详见 `SKILL.md` 的「从 v1 升级」），旧文件不删不改名。
