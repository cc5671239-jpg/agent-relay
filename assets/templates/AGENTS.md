## 2. 接手必读（按顺序）

1. `README.md` —— 项目全貌与文档地图
2. `PROJECT_CONTEXT.md` —— ⭐ 当前状态快照（最先看，最常变）
3. `ROADMAP.md` —— 阶段计划，本次任务属于哪个阶段
4. `DECISIONS.md` —— 已定决策，不要推翻或重新讨论
5. `CHANGELOG.md` —— 改过什么、为什么

## 3. 每次工作的固定流程

### 工作开始

1. 按顺序读上述 5 个文件
2. 对照 ROADMAP 确认本次任务属于哪个阶段
3. PROJECT_CONTEXT 的"下一步"与用户要求冲突时，先向用户确认再动手

### 工作结束（缺一不可）

1. 更新 `PROJECT_CONTEXT.md`（最后更新时间、最近执行 Agent、状态、下一步、风险）
2. `CHANGELOG.md` 顶部追加条目（日期 / **执行 Agent（工具+模型）** / 修改内容 / 原因 / 影响 / 下一步）——必须如实写明本次由哪个工具与模型执行
3. 重要设计或技术选择 → `DECISIONS.md` 追加新编号
4. 阶段推进 → 更新 `ROADMAP.md` 勾选项
5. **git 提交并推送**：`git add -A && git commit -m "..." && git push`——远端是唯一备份；配置自动部署时推送即上线；**不推送 = 工作只完成一半**
6. 向用户汇报：做了什么、发现了什么、下一步建议；确认可安全结束会话

## 4. 红线（不要做）

1. ❌ 不重命名、不删除核心治理文档
2. ❌ 内容不硬编码进代码（按项目的内容目录约定，如 `data/`）
3. ❌ 不引入新依赖 / 新框架而不在 `DECISIONS.md` 记录理由
4. ⚠️ 用户真实信息缺失时保留占位符并标 TODO，**不编造**
5. ❌ 上下文丢失 / 被压缩时立即重读必读文件，以文档为准，不凭残存记忆操作
6. ❌ 未经用户确认不删除或覆盖既有内容
